# 容器镜像格式

容器镜像的“标准格式”是 **OCI Image Format Specification**，它和 **OCI Runtime Spec** 一起构成容器生态互操作的基础。规范只定义数据长什么样、哈希如何计算、组件如何引用，不规定用什么工具、什么文件系统、什么运行时。

## 整体模型：四类组件，一个 Merkle DAG

一个 OCI 镜像由四类逻辑组件构成，实际落地为若干个**按内容哈希命名**的 Blob：

| 组件                    | 作用                                          | 媒体类型                                     |
| ----------------------- | --------------------------------------------- | -------------------------------------------- |
| **Image Index**（可选） | 多平台入口，`manifests` 数组指向多个 Manifest | `application/vnd.oci.image.index.v1+json`    |
| **Image Manifest**      | 物料清单，指向 config 和有序 layers           | `application/vnd.oci.image.manifest.v1+json` |
| **Image Configuration** | 运行时配置 + rootfs 的 diff_id 列表           | `application/vnd.oci.image.config.v1+json`   |
| **Filesystem Layers**   | 文件系统变更集                                | `...layer.v1.tar`（可带 `+gzip` / `+zstd`）  |

组件之间通过 **Descriptor** 引用。Descriptor 只有三个核心字段：

```json
{ "mediaType": "...", "digest": "sha256:...", "size": 1234 }
```

`digest` 是内容的密码学哈希（通常 SHA-256）。**引用关系不是“路径指向文件”，而是“哈希指向内容”**——改动任何一个字节，digest 就变，引用链自动断裂。这正是整份规范可验证性的根基。

- **Image Index** 的 `manifests` 数组里每个条目是一个 Descriptor，额外带 `platform` 对象（`architecture`、`os`、`variant`）。单平台镜像也可以有 Index，只是数组里只有一个条目。
- **Image Manifest** 的 `layers` 数组**顺序即叠加顺序**：索引 0 是最底层，依次向上。每个 layer 的 digest 是**压缩后** Blob 的哈希，用于传输校验。
- **Image Configuration** 包含两部分：
  - `config` 字段：`Env`、`Entrypoint`、`Cmd`、`User`、`WorkingDir` 等，是 runc 拼装 OCI Runtime Bundle 的输入。
  - `rootfs.diff_ids`：每层**解压后** tar 的 SHA-256，顺序与 manifest 的 layers 一一对应，用于文件系统层面的身份确认。
  - `history` 记录每条 Dockerfile 指令，但不改变文件系统的指令（如 `ENV`）标记 `empty_layer: true`，不占用 diff_id。
- **Layer** 是相对于父层的变化集，只包含新增/修改/删除三类。删除用 **whiteout 文件**表示：`.wh.<name>` 遮挡下层同名文件，`.wh..wh..opq` 表示整个目录被本层替代。tar 条目还需记录 mtime、uid/gid、mode、xattrs、符号链接、硬链接等属性。

**Merkle DAG 在容器镜像格式中的体现：**

| 节点        | 内容包含的子节点引用                                      |
| ----------- | --------------------------------------------------------- |
| Layer Blob  | 无（叶子）                                                |
| Config Blob | 无（叶子，但 `diff_ids` 是文本记录，不是 DAG 边，见后文） |
| Manifest    | `config` 的 Descriptor + `layers[]` 的 Descriptor         |
| Image Index | `manifests[]` 的 Descriptor                               |

```text
Index (sha256:A)
 ├─ Descriptor(digest=B) ──> Manifest(amd64) (sha256:B)
 │                              ├─ Descriptor(digest=C) ──> Config (sha256:C)   ← 叶子
 │                              ├─ Descriptor(digest=D) ──> Layer0 (sha256:D)  ← 叶子
 │                              └─ Descriptor(digest=E) ──> Layer1 (sha256:E)  ← 叶子
 └─ Descriptor(digest=F) ──> Manifest(arm64) (sha256:F)
                                ├─ Descriptor(digest=G) ──> Config (sha256:G)
                                └─ Descriptor(digest=E) ──> Layer1 (sha256:E)  ← 共享!
```

## OCI Layout：磁盘上到底怎么存

OCI Image Layout 定义了一个最小目录结构，用于在文件系统上存放镜像 Blob：

```
<image-root>/
├── oci-layout          # 必须存在，声明布局版本
├── index.json          # 必须存在，顶层入口（可以是 Image Index 或指向 Manifest）
└── blobs/
    └── sha256/
        ├── <digest-1>  # 一个 Blob（可能是 manifest、config 或 layer）
        ├── <digest-2>
        └── ...
```

## Docker 旧格式

历史上 Docker 有两套格式：

- **Docker Image Manifest v2 Schema 1**（已废弃，2018 年从 Registry 移除）。
- **Docker Image Manifest v2 Schema 2**：字段名与 OCI Manifest 基本一致，媒体类型前缀为 `application/vnd.docker.distribution.manifest.v2+json` 等。

OCI Image Spec 可以看作 v2 Schema 2 的标准化、去 Docker 化版本。两者的主要差异：

| 差异点       | Docker v2 Schema 2         | OCI Image Spec                              |
| ------------ | -------------------------- | ------------------------------------------- |
| 媒体类型前缀 | `application/vnd.docker.*` | `application/vnd.oci.*`                     |
| 多平台入口   | **manifest list**          | **Image Index**                             |
| 层压缩格式   | gzip                       | gzip、zstd、未压缩 tar                      |
| 额外字段     | —                          | `artifactType`、`subject`、`annotations` 等 |

所以 `docker save` 导出的目录里，根目录的 `manifest.json` + `repositories` 是**Docker 传统布局**，供 `docker load` 读取；`oci-layout` + `index.json` + `blobs/` 是 **OCI Layout**，供 containerd、skopeo、podman 等 OCI 工具读取。较新的导出工具会同时写出两套，以兼容新旧消费者。
