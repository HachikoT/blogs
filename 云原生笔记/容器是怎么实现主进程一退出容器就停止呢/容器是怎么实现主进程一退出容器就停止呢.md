一句话：**容器的主进程通常就是新 PID namespace 里的 PID 1；Linux 内核规定 PID 1 退出时，会杀死该 PID namespace 内所有进程。运行时再监控到这个退出事件，清理 cgroup、网络、挂载等资源，把容器标记为 stopped。**

具体链路大致是：

1. **创建容器时**
   - `docker/containerd/kubelet` 调用 `runc` 之类的运行时。
   - `runc` 通过 `clone/unshare` 创建新的 PID namespace、mount namespace、network namespace 等。
   - 你指定的启动命令，比如 `nginx`、`java -jar ...`，成为这个新 PID namespace 里的 **PID 1**。

2. **PID 1 的特殊性**
   - 在普通 Linux 系统里，PID 1 是 init，负责回收孤儿进程、转发信号等。
   - 在容器的 PID namespace 里，容器主进程就是这个小世界的 init。
   - 当这个 PID 1 退出时，内核会执行类似“杀掉该 PID namespace 里所有进程”的操作，向 namespace 内其他进程发送 `SIGKILL`，并阻止该 namespace 再创建新进程。

   所以不是 Docker 每隔几秒去看一眼，然后逐个杀进程，而是**内核先把容器内其他进程杀掉**。

3. **运行时监控和清理**
   - `containerd-shim` 或运行时父进程会通过 `waitpid`、`pidfd` 等等待容器 PID 1。
   - PID 1 一退出，shim 拿到退出码和退出原因。
   - shim 通知 containerd/dockerd：容器退出了。
   - 然后清理资源：删除 cgroup、卸载 rootfs、清理 veth/网络 namespace、释放容器元数据。
   - 容器状态变成 `exited/stopped`。


核心就是：**PID namespace 的 init 退出 = 内核杀整个 namespace；运行时监控到 init 退出 = 更新状态并清理资源。**
