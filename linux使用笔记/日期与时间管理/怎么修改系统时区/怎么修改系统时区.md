# 怎么修改系统时区

Linux 中的系统时区决定了时间戳如何转换成人类可读的本地时间。例如，同一个 UTC 时间，在上海显示为北京时间，在纽约则显示为北美东部时间。

修改时区不会修改硬件时钟或系统当前保存的时间戳，主要是改变“如何解释和显示时间”的规则。常见的时区名称来自 IANA 时区数据库，例如：

- `UTC`：协调世界时。
- `Asia/Shanghai`：中国标准时间。
- `America/New_York`：美国纽约时间。

## 使用 timedatectl 修改时区

### 查看当前时间和时区

```bash
rc@ubuntu:~$ timedatectl
               Local time: Sat 2026-09-19 08:55:39 PDT     
           Universal time: Sat 2026-09-19 15:55:39 UTC     
                 RTC time: Sat 2026-09-19 15:55:39         
                Time zone: America/Los_Angeles (PDT, -0700)
System clock synchronized: yes                             
              NTP service: active                          
          RTC in local TZ: no
```

### 查看可用时区

```bash
rc@ubuntu:~$ timedatectl list-timezones | grep Shanghai
Asia/Shanghai
```

不同发行版或不同版本的时区数据库，列表可能略有差异。中国大陆通常使用 `Asia/Shanghai`。

### 修改为上海时区

```bash
rc@ubuntu:~$ sudo timedatectl set-timezone Asia/Shanghai
```

修改后验证：

```bash
rc@ubuntu:~$ timedatectl 
               Local time: Sat 2026-09-19 23:57:22 CST
           Universal time: Sat 2026-09-19 15:57:22 UTC
                 RTC time: Sat 2026-09-19 15:57:22    
                Time zone: Asia/Shanghai (CST, +0800) 
System clock synchronized: yes                        
              NTP service: active                     
          RTC in local TZ: no
```

`set-timezone` 通常需要 root 权限，因为它要修改系统的时区配置文件或符号链接。

## timedatectl 修改时区时做了什么

`timedatectl` 是 systemd 提供的命令行工具。执行下面的命令时：

```bash
sudo timedatectl set-timezone Asia/Shanghai
```

大致会经过以下过程：

1. `timedatectl` 解析 `Asia/Shanghai`，确认它是系统时区数据库中的有效名称。
2. 它通过 systemd 的 `systemd-timedated` 服务请求修改系统时区。这个服务负责统一管理时间、时区、NTP 和硬件时钟设置。
3. `systemd-timedated` 将 `/etc/localtime` 设置为对应的时区数据库文件，通常是指向 `/usr/share/zoneinfo/Asia/Shanghai` 的符号链接。
4. 服务可能更新 `/etc/timezone`，但是否存在和是否更新取决于发行版。它不是 systemd 判断当前时区的唯一依据。
5. 后续调用 `date`、`localtime()`、Python 或其他语言时间库的进程，会根据 `/etc/localtime` 读取时区规则，把 UTC 时间转换成本地时间。

可以查看实际结果：

```bash
rc@ubuntu:~$ ll /etc/localtime 
lrwxrwxrwx 1 root root 33 Sep 19 23:57 /etc/localtime -> /usr/share/zoneinfo/Asia/Shanghai
rc@ubuntu:~$ cat /etc/timezone 
Asia/Shanghai
```

修改时区后，已经运行的程序不一定会立即重新读取时区文件。有些程序会在启动时缓存时区信息，因此修改后重启相关服务通常更稳妥；新启动的程序会直接读取新的配置。

## `/etc/localtime` 与 `/etc/timezone` 的关系

这两个文件虽然都与时区相关，但角色和格式完全不同。

| 特性         | `/etc/localtime`                                                                   | `/etc/timezone`                                                      |
| :----------- | :--------------------------------------------------------------------------------- | :------------------------------------------------------------------- |
| **文件类型** | **二进制文件**（或指向二进制文件的符号链接）                                       | **纯文本文件**                                                       |
| **内容**     | 包含完整的时区规则数据（如夏令时转换规则）                                         | 仅包含一行时区标识符，如 `Asia/Shanghai`                             |
| **作用**     | **系统时区的权威来源**，C 库和大多数程序通过它来确定本地时间                       | **辅助性配置文件**，主要供部分应用程序或旧版系统读取，现已逐渐被弃用 |
| **关系**     | 二者应始终保持同步。`/etc/timezone` 相当于 `/etc/localtime` 所代表时区的“文本标签” |                                                                      |

**关键要点**：
*   **权威来源**：现代 Linux 系统（尤其是较新的 Debian/Ubuntu 和所有 systemd 发行版）以 `/etc/localtime` 为准。如果两者不一致，系统会优先信任 `/etc/localtime`。
*   **存在原因**：`/etc/timezone` 最初源于 Debian 系统，用于以文本形式记录时区，方便用户和脚本查看。尽管其作用在减弱，但为了向后兼容，许多发行版仍会保留它。
*   **手动修改**：在使用 `timedatectl set-timezone` 时，系统通常会自动同时更新 `/etc/localtime` 的链接和 `/etc/timezone` 的内容，因此你无需手动干预。

## 为什么中国时区里面只有上海没有北京

`Asia/Shanghai` 并不是说只有上海使用这个时区，而是 IANA 时区数据库选择了一个代表性城市作为该时区的名称。北京、上海、广州、深圳等中国大陆城市当前使用相同的 UTC+08:00 规则，因此没有必要为每个城市建立一个内容完全相同的时区条目。

选择 `Asia/Shanghai` 主要有历史和兼容性原因：

- 上海是国际上较早使用和记录现代标准时间的中国城市之一。
- IANA 需要为一组具有相同时间规则的地区选择一个代表名称，而不是为每个城市重复维护规则。
- 很多软件、配置和资料长期使用 `Asia/Shanghai`，继续保留它有利于兼容。
